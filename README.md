# Бот ответов по обновляемому прайсу

Отдельный новый проект. Он получает прайс из другого Telegram-бота, сохраняет изменения цен, получает новые запросы из выбранных групп и отвечает на исходное сообщение по последней успешно загруженной версии. Управление — через собственного бота в личке. Можно также загружать прайс вручную. Связь с Tech Monitor не требуется.

**Размещение на Railway:** [пошаговая инструкция](RAILWAY.md). Поддерживаются постоянный Volume и перенос авторизации Telegram через секретную переменную окружения.

## Быстрый запуск

Нужен Python 3.12 или новее. Скачай репозиторий и открой терминал в его папке.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

На Windows активируй окружение командой `.venv\Scripts\activate`.

1. Создай нового бота в [@BotFather](https://t.me/BotFather), команда `/newbot`. Скопируй токен в `BOT_TOKEN`.
2. Получи собственные `API_ID` и `API_HASH` на [my.telegram.org](https://my.telegram.org), раздел API development tools.
3. Скопируй `.env.example` в `.env` и заполни `API_ID`, `API_HASH`, `BOT_TOKEN`.
4. Подключи свой аккаунт локально:

   ```bash
   python -m catalog_bot login
   ```

   Введи номер, код Telegram и, если используется, пароль 2FA в терминале. Скрипт выведет Telegram ID аккаунта. Если управлять ботом будешь с этого же аккаунта, запиши этот ID в `OWNER_ID` в `.env`. Иначе укажи ID другого своего аккаунта управления.
5. Запусти:

   ```bash
   python -m catalog_bot run
   ```

6. Открой личку с новым ботом и нажми Start. Настрой автоисточник или загрузи прайс через `/price`, выбери группы, проверь запрос и включи ответы через `/run`.

Аккаунт должен уже состоять в выбранных группах и иметь право писать в них. Добавлять управляющего бота в эти группы не требуется. При локальном запуске файл авторизации хранится в папке `data`. Для Railway команда `python -m catalog_bot session-env` экспортирует авторизацию в приватный файл `data/railway-session.env`; его содержимое переносится в Railway Variables по [инструкции](RAILWAY.md).

## Прайс из другого Telegram-бота

В `.env.example` уже указаны переданные источник и команда. При копировании в `.env` они сохранятся:

```dotenv
PRICE_BOT_USERNAME=@tech_online_seller_bot
PRICE_REQUEST_TEXT=/prices
PRICE_BUTTON_TEXT=
PRICE_REFRESH_SECONDS=600
```

После авторизации пользовательского аккаунта приложение будет отправлять `/prices` боту `@tech_online_seller_bot`. Это настройки, полученные от пользователя; живой ответ источника при подготовке не проверялся. Если источник позже изменится и прайс станет вызываться кнопкой, оставь `PRICE_REQUEST_TEXT` пустым и заполни `PRICE_BUTTON_TEXT` точным текстом кнопки. Поддерживаются обычная кнопка, отправляющая текст, и inline-кнопка с callback. Нужная кнопка должна присутствовать в последних 20 сообщениях источника. Многоступенчатые меню требуют настройки под конкретного бота. URL-кнопки и запросы контакта или геолокации не нажимаются.

После перезапуска приложение запрашивает полный прайс, затем повторяет запрос каждые 600 секунд после завершения предыдущего обновления. Интервал можно изменить (минимум 60 секунд). `/refresh` запускает обновление вручную. `PRICE_BOT_USERNAME` пустой — автоисточник отключён. Для первого запроса к живому источнику ещё нужно авторизовать аккаунт и запустить приложение с заполненным `.env`.

Поддерживается формат из присланного примера:

```text
Цены на Все товары
• Galaxy S26 12/256 Black SM-S942B/DS🇿🇦
🇿🇦 От 1 шт - 60 000

Всего найдено 1 товаров
```

Это одна запись из предоставленного примера, а итоговая строка выше относится только к ней. В тестах `examples/supplier_price_excerpt.txt` используется фрагмент из 14 товарных блоков; полный исходный список из сообщения не включён. Также отдельно проверяется сбор синтетического прайса из 425 блоков.

Сборщик объединяет несколько новых сообщений ответа и принимает редактирование сообщения с нажатой кнопкой. Полнота проверяется по строке `Всего найдено N товаров`: количество товарных блоков должно совпасть с N. До этого рабочий прайс не заменяется. На получение ответа отводится 120 секунд. Раздельные служебные сообщения вроде меню не считаются товарными блоками.

`/price` позволяет загрузить тот же формат текстом, частями или файлом `.txt`. При ручной загрузке без итоговой строки можно нажать «Завершить загрузку части прайса»: обновятся только переданные позиции того же источника, остальные сохранятся. Для смены источника при уже существующем списке нужен полный прайс. Автоматическое получение всегда требует полного прайса.

Точное совпадение названия, региона и порога количества объединяет одинаковые дубли. Если такой дубль содержит другую цену, обновление отклоняется. Разные регионы сохраняются отдельно. Флаги у названия и у цены сохраняются оба; если они противоречат друг другу, строка видна в `/changes`, но не участвует в автоматических предложениях. Флаг не используется для угадывания SIM/eSIM.

`От 1 шт` — минимальное количество для этой цены, а не остаток. Источник не сообщает складское количество, поэтому ответ начинается с «По актуальному прайсу». Цены «от 5 шт» и другие оптовые уровни сохраняются, но автоматически не предлагаются: эта версия использует цены от одной штуки и не рассчитывает цену по оптовому количеству запроса. По умолчанию цена используется без наценки.

`/changes` показывает время обновления в Москве и последние изменения `старая цена → новая цена`, добавления и исчезновения предложений. Первый прайс служит исходной версией для сравнения. Удаление возможно только после полного обновления; это означает исчезновение из прайса, а не подтверждённое отсутствие на складе. После успешного обновления следующие ответы используют новую цену. Владелец получает уведомление при первом получении, изменениях и восстановлении обновлений; неизменившийся прайс при фоновом опросе лишнего уведомления не создаёт.

Если источник недоступен или полный прайс не пришёл, предыдущая версия и история остаются в базе, но ответы по ценам приостанавливаются до успешного обновления. При старте с настроенным автоисточником приложение также дожидается свежего прайса. Выбранный режим `/run` при этом сохраняется. После успешной загрузки предложения возобновляются, если они были включены.

Загрузка `/catalog` — отдельный способ задать свой список. При настроенном автоисточнике очередной полный прайс поставщика заменит ручной список; выбирай один способ ведения рабочего каталога.

## Формат списка

Через `/catalog` отправь текст или `.txt`/`.csv` до 1 МБ, не больше 3000 позиций. Поддерживаются UTF-8 и Windows-1251 для файлов. Новый список заменяет предыдущий целиком. При ошибке старый список сохраняется.

Одна строка — одна комплектация. Столбцы разделяются `|`, CSV с заголовками также допускает `;`, запятую и табуляцию.

```text
Название | Цена | Остаток | Артикул
iPhone 17 256GB Black SIM | 85000 | 2 |
iPhone 17 Pro Max 256GB Silver SIM+eSIM | 115000 | 1 | MDE44
Marshall Emberton III Black | 12000 | 3 |
```

Цены в примере собственного списка вымышленные. Замени их реальными данными. Все цены — в рублях. Пустая цена означает ответ без цены; отсутствующий остаток — 1; остаток 0 исключает товар из предложений. Артикул необязателен. Поддерживается также `название — цена` или просто список названий по строкам. Файл `/sample` показывает формат, `/stock` выгружает текущий список либо прайс с сохранёнными региональными полями.

При предложении товара остаток не уменьшается: отправка ответа не означает продажу. Обновляй список по мере продаж. Файл Excel нужно сначала сохранить как CSV; фотографии и скриншоты прайсов эта версия не распознаёт.

## Подбор

- «Нужен iPhone 17» → имеющиеся комплектации обычного iPhone 17.
- «iPhone 17 Pro Max 256 silver sim» → та же модель, версия, память, цвет и поддержка физической SIM.
- «18 pro max 1tb glacier esim» → узнаёт короткое название iPhone, если в прайсе нет подходящей модели другого семейства.
- «MDE44» → только товар с таким артикулом либо точным кодом в названии.
- «Продам iPhone 17» → ответ не отправляется.
- «Куплю iPhone 17 до 80 000» → только позиции с указанной ценой до бюджета.

Поддерживаются распространённые русские и английские названия, цвета, iPhone, нумерованные iPad/Pixel, Samsung S/A, память и RAM, состояние, размеры очков и точное сопоставление остальных названий. Характеристика, явно указанная в запросе, должна присутствовать у товара. Если память или цвет в запросе не указаны, показываются подходящие варианты из прайса. Обычная модель, Pro, Pro Max, Pro XL, Fold и FE считаются разными версиями. Несколько указанных цветов обязательны одновременно; «или» позволяет выбрать один из цветов. Для маркировок F/frame/оправа и L/lens/линзы цвет проверяется отдельно: чёрная оправа с зелёными линзами не заменяется зелёной оправой с чёрными линзами. Неподдерживаемое свободное описание может быть пропущено.

В этой версии маркировка `SIM` означает наличие физической SIM, включая `SIM+eSIM`. Явный запрос `SIM+eSIM` требует обеих маркировок у товара. Маркировка `eSIM` без SIM означает вариант только с eSIM. `2 SIM`/`dual SIM` — отдельная комплектация. Указывай эти значения в списке последовательно.

Сообщения без «куплю» по умолчанию обрабатываются: запрос в группе может состоять только из названия товара. В обсуждательных группах используй `/bare off`: тогда требуется явное намерение купить. Классификация основана на правилах, поэтому все свободные формулировки и опечатки не гарантируются. Сложные отрицания пропускаются, явно смешанные сообщения «куплю/продам» тоже. Проверяй свои реальные примеры через `/test` перед включением.

Подбор проходит отдельные этапы: намерение → структурированная спецификация → точная модель/версия или полный артикул → все указанные ограничения → допуск позиции из текущего прайса. Артикул (включая полный код вроде RW4012 в названии поставщика) не отменяет проверку цвета, памяти, NFC, состояния и других ограничений. Отдельный бренд вроде «Sony» не считается моделью. Буквенные модели без номера допустимы при полном совпадении содержательной части названия с прайсом.

Телефон не заменяется чехлом, стеклом, зарядкой или запчастью. Б/у, восстановленные и позиции с распознанными признаками повреждения/витрины не предлагаются без соответствующего запроса; предупреждения поставщика дополнительно исключают позицию. `NFC`, `NO NFC`/«без NFC» и неизвестный NFC различаются. `Cellular` и `LTE` означают сотовую версию; `Wi-Fi+LTE` подходит под Cellular, но не под запрос версии только Wi-Fi. SIM не выводится из страны.

«256 512» без «или» — неоднозначность, ответа не будет. «256 или 512» допускает обе памяти; «чёрный или зелёный» не превращает конфликт памяти в альтернативу. Несколько моделей в одной строке безопаснее разделить строками. Бюджет разбирается отдельно от памяти. `/test` показывает распознанные признаки, причины пропуска запроса и число позиций, отсеянных каждым фильтром; отсутствие признака в прайсе не считается подтверждением.

Один ответ содержит не больше пяти позиций и число дополнительных вариантов. Несколько товарных строк разбираются раздельно; характеристики соседних товаров не склеиваются.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Меню |
| `/price` | Загрузить прайс поставщика, в том числе частями |
| `/refresh` | Запросить свежий прайс из настроенного бота |
| `/changes` | Последнее обновление, изменения цен и спорные строки |
| `/catalog` | Заменить список товаров |
| `/sample` | Скачать учебный пример |
| `/stock` | Скачать текущий список |
| `/chats` | Выбрать группы аккаунта |
| `/test текст запроса` | Посмотреть подбор и ответ без отправки в группы |
| `/run` | Включить автоматические ответы |
| `/pause` | Выключить ответы |
| `/bare on` / `/bare off` | Учитывать / пропускать названия без «куплю» |
| `/intro` | Изменить начало ответа |
| `/status` | Наличие, группы и режим работы |
| `/tail` | Последние результаты отправки |
| `/cancel` | Отменить текущий ввод |

Доступ к управлению имеет только `OWNER_ID` и только в личке. Ответы идут в исходные группы от подключённого аккаунта. Уведомления о результатах приходят владельцу. Личные сообщения покупателям не отправляются.

## Хранение и отправка

`data/catalog.sqlite3` хранит список, настройки, выбранные группы, историю цен и журнал отправок. `data/account.session` — авторизация Telegram. Эти файлы и `.env` не публикуй в GitHub. Они исключены из сборки Docker и из Git через соответствующие ignore-файлы.

Изначально ответы выключены. После `/run` выбранный режим сохраняется при обычном перезапуске. Повторно полученное сообщение не отправляется заново; одинаковый текст одного покупателя в разных группах подавляется на 120 секунд. Это время меняется через `DEDUP_SECONDS`. Лимит — 10 ответов в минуту (`MAX_REPLIES_PER_MINUTE`); превышающие лимит сообщения пропускаются. История групп не перечитывается, пересланные и старые сообщения старше двух минут пропускаются.

Если Telegram сообщает ошибку отправки или соединение обрывается, автоматические ответы приостанавливаются. Для неоднозначного результата повторной отправки нет; проверь исходный чат и `/tail`. Если процесс оборвался во время отправки, при запуске такая запись также получает статус «неизвестно» и ответы ставятся на паузу. Это уменьшает риск дублирования, но не гарантирует доставку каждого предложения.

Один экземпляр приложения использует одну папку `data`. Её нужно сохранять на постоянном диске. Утрата папки означает потерю наличия, настроек и дедупликации.

## Docker на сервере

После заполнения `.env`:

```bash
docker compose build
docker compose run --rm bot python -m catalog_bot login
docker compose up -d
docker compose logs -f
```

`compose.yaml` подключает постоянную папку `./data`. Аккаунт авторизуется отдельной интерактивной командой, а затем приложение работает в фоне. Для остановки: `docker compose down`. Сервер должен иметь доступ к Telegram.

## Проверки без Telegram

```bash
python -m catalog_bot demo
python -m catalog_bot check-catalog examples/catalog.txt
python -m catalog_bot check-price examples/supplier_price_excerpt.txt
python -m unittest discover -s tests -v
```

Тесты проверяют подбор, импорт прайса, историю цен, нулевые остатки, неизвестный остаток, регионы, дубли, неполные ответы, 425 синтетических товарных блоков, перезапуск, ошибку отправки и команды управления. Проверены перенос сессии для Railway и защита от записи данных за пределами Volume. Автополучение по команде и по кнопке проверяется с локальным заменителем Telegram. Подключение к реальным Telegram-аккаунтам, получение прайса от живого поставщика и живая отправка при подготовке проекта не выполнялись.
