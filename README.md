# Бот ответов по обновляемому прайсу

Отдельный новый проект. Он получает прайс из другого Telegram-бота, сохраняет изменения цен, получает новые запросы из выбранных групп и отвечает на исходное сообщение по последней успешно загруженной версии. Управление — через собственного бота в личке. Можно также загружать прайс вручную. Связь с Tech Monitor не требуется.

**Размещение на Railway:** [пошаговая инструкция](RAILWAY.md). Авторизация выполняется прямо в управляющем боте через /loginqr или /login и сохраняется на постоянном Volume.

**Словари распознавания и проверки:** [RECOGNITION.md](RECOGNITION.md). Названия, транслитерация и известные опечатки хранятся отдельно от кода; для проверки есть команда `python -m catalog_bot check-recognition`.

## Быстрый запуск

Нужен Python 3.12 или новее. Скачай репозиторий и открой терминал в его папке.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

На Windows активируй окружение командой `.venv\Scripts\activate`.

1. Создай нового управляющего бота через [@BotFather](https://t.me/BotFather), команда `/newbot`. Скопируй токен в `BOT_TOKEN`.
2. Получи `API_ID` и `API_HASH` на [my.telegram.org](https://my.telegram.org), раздел API development tools.
3. Скопируй `.env.example` в `.env`, заполни `API_ID`, `API_HASH`, `BOT_TOKEN` и свой числовой Telegram ID в `OWNER_ID`.
4. Запусти `python -m catalog_bot run`. Управляющий бот работает даже до входа в пользовательский аккаунт.
5. В личке со своим ботом отправь `/loginqr`: открой QR на компьютере, а на телефоне выбери Telegram → Настройки → Устройства → Подключить устройство. Отсканируй QR и подтверди вход; введи пароль 2FA, если бот его запросит. Альтернатива — `/login`: номер с кодом страны → код через пробелы → пароль 2FA. Отмена — `/cancel`. QR обновляется в течение пяти минут и удаляется после завершения или отмены. Значения кода, пароля и QR-токена не печатаются в логи и не записываются в настройки.
6. Проверь `/status`, задай `/markup`, выбери `/chats`, проверь запрос через `/test` и включи `/run`.

Аккаунт должен уже состоять в выбранных группах и иметь право писать в них. Авторизация автоматически сохраняется в `data/account.session`; при перезапуске повторный код не требуется, пока Telegram не отозвал вход. После нового входа ответы выключены, пока владелец не включит их. После обычного перезапуска с действующей авторизацией сохраняется прежний режим ответов.

`/chats` и «Группы» показывают сохранённый список и загружают недостающие группы в фоне.
Найденные группы можно выбирать, пока остальные ещё загружаются. При FloodWait бот
сохраняет найденное, выжидает срок Telegram и продолжает с той же страницы. Панель
обновляется автоматически. Ошибка загрузки не означает, что групп в аккаунте нет.
Список сохраняется на Volume отдельно для текущего аккаунта. Просмотр страниц и
выбор групп не перечитывают все диалоги. «Обновить» или `/chats refresh` запускают
обновление списка; повторные нажатия используют уже идущую загрузку. Завершённый
список автоматически обновляется при открытии после 15 минут, а повторное принудительное
обновление допускается спустя минуту. Архивные группы входят в поиск; лички и
каналы без группового чата не показываются.

На Railway достаточно сервиса, Volume `/data` и переменных из [RAILWAY.md](RAILWAY.md). Переменная `TELEGRAM_SESSION` для нового запуска не нужна. Для совместимости со старыми установками корректная строковая сессия ещё поддерживается и переносится в постоянный файл автоматически; после успешного входа используется сохранённый файл. Продвинутые локальные команды `login` и `session-env` также остаются доступны.

## Прайс из другого Telegram-бота

В `.env.example` уже указаны переданные источник и команда. При копировании в `.env` они сохранятся:

```dotenv
PRICE_BOT_USERNAME=@tech_online_seller_bot
PRICE_REQUEST_TEXT=/prices
PRICE_BUTTON_TEXT=
PRICE_REFRESH_SECONDS=600
```

После авторизации пользовательского аккаунта приложение будет отправлять `/prices` боту `@tech_online_seller_bot`. Это настройки, полученные от пользователя; живой ответ источника при подготовке не проверялся. Если источник позже изменится и прайс станет вызываться кнопкой, оставь `PRICE_REQUEST_TEXT` пустым и заполни `PRICE_BUTTON_TEXT` точным текстом кнопки. Поддерживаются обычная кнопка, отправляющая текст, и inline-кнопка с callback. Нужная кнопка должна присутствовать в последних 20 сообщениях источника. Многоступенчатые меню требуют настройки под конкретного бота. URL-кнопки и запросы контакта или геолокации не нажимаются.

Кнопка «Запросить прайс», `/price` и `/refresh` запрашивают полный прайс у настроенного бота поставщика. Ручная загрузка вынесена отдельно: «Загрузить вручную» или `/uploadprice`.

Кнопка «Автообновление» и `/timer` показывают текущий интервал, время следующего запроса по Москве и оставшееся время. Есть интервалы 5/10/30/60 минут и ввод своего значения от 1 до 1440 минут. Например, `/timer 15` обновляет каждые 15 минут, `/timer off` выключает фоновые запросы, `/timer on` возвращает сохранённый интервал. Ручной запрос продолжает работать при выключенном таймере. Настройки сохраняются в базе и применяются сразу, без изменения Railway Variables.

При включённом таймере после подключения аккаунта/перезапуска запрашивается свежий полный прайс. Затем отсчёт начинается от завершения предыдущего запроса. Одновременное нажатие кнопки и срабатывание таймера не отправляют две команды поставщику. FloodWait Telegram соблюдается. `PRICE_REFRESH_SECONDS=600` задаёт начальный интервал, если он ещё не выбран в боте. `PRICE_BOT_USERNAME` пустой — источник не настроен; доступна ручная загрузка.

Поддерживается формат из присланного примера:

```text
Цены на Все товары
• Galaxy S26 12/256 Black SM-S942B/DS🇿🇦
🇿🇦 От 1 шт - 60 000

Всего найдено 1 товаров
```

Это одна запись из предоставленного примера, а итоговая строка выше относится только к ней. В тестах `examples/supplier_price_excerpt.txt` используется фрагмент из 14 товарных блоков; полный исходный список из сообщения не включён. Также отдельно проверяется сбор синтетического прайса из 425 блоков.

Сборщик объединяет несколько новых сообщений ответа и принимает редактирование сообщения с нажатой кнопкой. Полнота проверяется по строке `Всего найдено N товаров`: количество товарных блоков должно совпасть с N. До этого рабочий прайс не заменяется. На получение ответа отводится 120 секунд. Раздельные служебные сообщения вроде меню не считаются товарными блоками.

`/uploadprice` позволяет загрузить тот же формат текстом, частями или файлом `.txt`. При ручной загрузке без итоговой строки можно нажать «Завершить загрузку части прайса»: обновятся только переданные позиции того же источника, остальные сохранятся. Для смены источника при уже существующем списке нужен полный прайс. Автоматическое получение всегда требует полного прайса.

Точное совпадение названия, региона и порога количества объединяет одинаковые дубли. Если такой дубль содержит другую цену, обновление отклоняется. Разные регионы сохраняются отдельно. Флаги у названия и у цены сохраняются оба; если они противоречат друг другу, строка видна в `/changes`, но не участвует в автоматических предложениях. Флаг не используется для угадывания SIM/eSIM.

`От 1 шт` — минимальное количество для этой цены, а не остаток. Источник не сообщает складское количество, поэтому ответ начинается с «По актуальному прайсу». Цены «от 5 шт» и другие оптовые уровни сохраняются, но автоматически не предлагаются: эта версия использует цены от одной штуки и не рассчитывает цену по оптовому количеству запроса. По умолчанию наценка равна нулю; её можно настроить через `/markup`.

`/changes` показывает время обновления в Москве и последние изменения `старая цена → новая цена`, добавления и исчезновения предложений. Первый прайс служит исходной версией для сравнения. Удаление возможно только после полного обновления; это означает исчезновение из прайса, а не подтверждённое отсутствие на складе. После успешного обновления следующие ответы используют новую цену. Владелец получает уведомление при первом получении, изменениях и восстановлении обновлений; неизменившийся прайс при фоновом опросе лишнего уведомления не создаёт.

Если источник недоступен или полный прайс не пришёл, предыдущая версия и история остаются в базе, но ответы по ценам приостанавливаются до успешного обновления. При старте с настроенным автоисточником приложение также дожидается свежего прайса. Выбранный режим `/run` при этом сохраняется. После успешной загрузки предложения возобновляются, если они были включены.

Загрузка `/catalog` — отдельный способ задать свой список. При настроенном автоисточнике очередной полный прайс поставщика заменит ручной список; выбирай один способ ведения рабочего каталога.

## Наценка

Кнопка «💸 Наценка» или `/markup` показывает текущие правила, категории и справку. Все изменения доступны только владельцу в личке и сохраняются при перезапуске. Примеры ниже задают реальные правила после отправки команды; при первом запуске все цены идут без наценки.

| Команда | Результат |
| --- | --- |
| `/markup default fixed 1000` | Общее правило: цена поставщика + 1 000 ₽ |
| `/markup phones percent 2` | Телефоны: цена поставщика × 1,02 |
| `/markup tablets fixed 1500` | Планшеты: цена поставщика + 1 500 ₽ |
| `/markup phones off` | Телефоны без наценки, даже если общее правило ненулевое |
| `/markup phones clear` | Удалить отдельное правило телефонов и применять общее |
| `/markup default off` | Общее правило 0; отдельные правила сохраняются |
| `/markup reset` | Убрать все наценки |

Правило категории **заменяет** общее. Фиксированная сумма и процент не складываются. Дробные значения можно писать с точкой или запятой, например `/markup phones percent 2,5`. Отрицательные значения, NaN, Infinity и экспоненциальная запись не допускаются. Итоговая цена округляется до копеек, половина копейки — вверх.

Категории: `phones` — телефоны, `tablets` — планшеты, `laptops` — ноутбуки, `wearables` — часы/трекеры/кольца, `headphones` — наушники, `glasses` — очки, `cameras` — камеры, `consoles` — игровые консоли, `accessories` — аксессуары и питание, `audio` — микрофоны и аудиоустройства, `other` — прочее. Категория определяется по типу и известному семейству товара: Pixel Watch — часы, Xiaomi Pad — планшет, Insta360 Mic — аудио, DJI Power — питание. Одного бренда недостаточно для отнесения к телефонам. Неопознанный тип попадает в `other`.

Закупочная цена хранится отдельно от расчёта продажи: `/stock` выгружает исходные цены, `/changes` показывает изменения цен поставщика. После обновления прайса наценка применяется к новой закупочной цене один раз. Перезапуск и повторный запрос её не накапливают. Если исходная цена отсутствует, наценка не превращается в цену товара.

Автоответы и `/test` используют одинаковую итоговую цену. Бюджет покупателя также проверяется **после наценки**: закупка 91 500 ₽ и наценка 2% дают 93 330 ₽, поэтому запрос «до 93 000» не получит это предложение. При изменении правила во время подбора устаревший ответ отменяется. В ответ покупателю попадает только итоговая цена.

Подбор и наценка работают локально, без вызовов ИИ и без расходов на токены ИИ.

## Формат списка

Через `/catalog` отправь текст или `.txt`/`.csv` до 1 МБ, не больше 3000 позиций. Поддерживаются UTF-8 и Windows-1251 для файлов. Новый список заменяет предыдущий целиком. При ошибке старый список сохраняется.

Одна строка — одна комплектация. Столбцы разделяются `|`, CSV с заголовками также допускает `;`, запятую и табуляцию.

```text
Название | Цена | Остаток | Артикул
iPhone 17 256GB Black SIM | 85000 | 2 |
iPhone 17 Pro Max 256GB Silver SIM+eSIM | 115000 | 1 | MDE44
Marshall Emberton III Black | 12000 | 3 |
```

Цены в примере собственного списка вымышленные. Замени их реальными данными. Все цены — в рублях. Пустая цена означает ответ без цены; отсутствующий остаток — 1; остаток 0 исключает товар из предложений. Артикул необязателен. Поддерживается также `название — цена` или просто список названий по строкам. Файл `/sample` показывает формат, `/stock` выгружает текущий список либо прайс с сохранёнными региональными полями.

При предложении товара остаток не уменьшается: отправка ответа не означает продажу. Обновляй список по мере продаж. Файл Excel нужно сначала сохранить как CSV; фотографии и скриншоты прайсов эта версия не распознаёт.

## Подбор

- «Нужен iPhone 17» → имеющиеся комплектации обычного iPhone 17.
- «iPhone 17 Pro Max 256 silver sim» → та же модель, версия, память, цвет и поддержка физической SIM.
- «18 pro max 1tb glacier esim» → узнаёт короткое название iPhone, если в прайсе нет подходящей модели другого семейства.
- «MDE44» → только товар с таким артикулом либо точным кодом в названии.
- «Продам iPhone 17» → ответ не отправляется.
- «Куплю iPhone 17 до 80 000» → только позиции с указанной ценой до бюджета.

Поддерживаются распространённые русские и английские названия, цвета, iPhone, нумерованные iPad/Pixel, Samsung S/A, память и RAM, состояние, размеры очков и точное сопоставление остальных названий. Характеристика, явно указанная в запросе, должна присутствовать у товара. Если память или цвет в запросе не указаны, показываются подходящие варианты из прайса. Обычная модель, Pro, Pro Max, Pro XL, Fold и FE считаются разными версиями. Несколько указанных цветов обязательны одновременно; «или» позволяет выбрать один из цветов. Для маркировок F/frame/оправа и L/lens/линзы цвет проверяется отдельно: чёрная оправа с зелёными линзами не заменяется зелёной оправой с чёрными линзами. Неподдерживаемое свободное описание может быть пропущено.

В этой версии маркировка `SIM` означает наличие физической SIM, включая `SIM+eSIM`. Явный запрос `SIM+eSIM` требует обеих маркировок у товара. Маркировка `eSIM` без SIM означает вариант только с eSIM. `2 SIM`/`dual SIM` — отдельная комплектация. Указывай эти значения в списке последовательно.

Сообщения без «куплю» по умолчанию обрабатываются: запрос в группе может состоять только из названия товара. В обсуждательных группах используй `/bare off`: тогда требуется явное намерение купить. Классификация основана на правилах, поэтому все свободные формулировки и опечатки не гарантируются. Сложные отрицания пропускаются, явно смешанные сообщения «куплю/продам» тоже. Проверяй свои реальные примеры через `/test` перед включением.

Подбор проходит отдельные этапы: намерение → нормализация известных написаний → бренд и семейство/линейка → точная модель/версия или полный артикул → все указанные ограничения → допуск позиции из текущего прайса. Запрос iPhone не допускает Xiaomi или другой бренд, даже при том же номере и памяти и отсутствии подходящего Apple. Xiaomi, Redmi и POCO также не становятся взаимозаменяемыми линейками. Артикул (включая полный код вроде RW4012 в названии поставщика) не отменяет проверку бренда, цвета, памяти, NFC, состояния и других ограничений. Слова внутри артикула не считаются требованиями покупателя: код с `USED` не разрешает предлагать б/у.

Отдельный бренд вроде «Sony» не считается моделью. Буквенные модели без номера допустимы при полном совпадении содержательной части названия с прайсом. Поддерживаются известные варианты вроде «сасунг», «айфон17промакс», `17PM`, `1сим` и кириллические Samsung-серии в контексте бренда. Ограниченная коррекция брендовой опечатки требует единственного соответствия; неизвестные слова сохраняются. Номер модели, буквенный суффикс, память и артикул по похожести не исправляются. Политика и пополнение словарей описаны в [RECOGNITION.md](RECOGNITION.md).

Телефон не заменяется чехлом, стеклом, зарядкой или запчастью. Б/у, восстановленные и позиции с распознанными признаками повреждения/витрины не предлагаются без соответствующего запроса; предупреждения поставщика дополнительно исключают позицию. `NFC`, `NO NFC`/«без NFC» и неизвестный NFC различаются. `Cellular` и `LTE` означают сотовую версию; `Wi-Fi+LTE` подходит под Cellular, но не под запрос версии только Wi-Fi. SIM не выводится из страны.

«256 512» без «или» — неоднозначность, ответа не будет. «256 или 512» допускает обе памяти; «чёрный или зелёный» не превращает конфликт памяти в альтернативу. Несколько моделей в одной строке безопаснее разделить строками. Бюджет разбирается отдельно от памяти. `/test` показывает распознанные признаки, причины пропуска запроса и число позиций, отсеянных каждым фильтром; отсутствие признака в прайсе не считается подтверждением.

Один ответ содержит не больше пяти позиций и число дополнительных вариантов. Несколько товарных строк разбираются раздельно; характеристики соседних товаров не склеиваются. Список коротких названий без «куплю» допускается даже при общей длине больше ограничения для одного названия, если включён `/bare on`. Каждая строка проходит проверку намерения.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Меню |
| `/login` | Подключить пользовательский аккаунт по номеру, коду и 2FA |
| `/loginqr` | Подключить аккаунт по QR через Telegram на телефоне; 2FA поддерживается |
| `/price` | Запросить прайс у настроенного бота поставщика |
| `/uploadprice` | Загрузить прайс вручную, в том числе частями |
| `/timer` | Интервал автообновления, время следующего запроса; /timer 15, /timer off |
| `/refresh` | Запросить свежий прайс из настроенного бота |
| `/changes` | Последнее обновление, изменения цен и спорные строки |
| `/markup` | Фиксированная или процентная наценка, общее правило и категории |
| `/catalog` | Заменить список товаров |
| `/sample` | Скачать учебный пример |
| `/stock` | Скачать текущий список |
| `/chats` | Выбрать группы аккаунта |
| `/test текст запроса` | Посмотреть подбор и ответ без отправки в группы |
| `/run` | Включить автоматические ответы |

Доступ к управлению имеет только `OWNER_ID` и только в личке. Ответы идут в исходные группы от подключённого аккаунта. Уведомления о результатах приходят владельцу. Личные сообщения покупателям не отправляются.

## Хранение и отправка

`data/catalog.sqlite3` хранит список, настройки, выбранные группы, историю цен и журнал отправок. `data/account.session` — авторизация Telegram. Эти файлы и `.env` не публикуй в GitHub. Они исключены из сборки Docker и из Git через соответствующие ignore-файлы.

Изначально ответы выключены. После `/run` выбранный режим сохраняется при обычном перезапуске. Повторно полученное сообщение не отправляется заново; одинаковый текст одного покупателя в разных группах подавляется на 120 секунд. Это время меняется через `DEDUP_SECONDS`. Лимит — 10 ответов в минуту (`MAX_REPLIES_PER_MINUTE`); превышающие лимит сообщения пропускаются. История групп не перечитывается, пересланные и старые сообщения старше двух минут пропускаются.

Если Telegram сообщает ошибку отправки или соединение обрывается, автоматические ответы приостанавливаются. Для неоднозначного результата повторной отправки нет; проверь исходный чат и `/tail`. Если процесс оборвался во время отправки, при запуске такая запись также получает статус «неизвестно» и ответы ставятся на паузу. Это уменьшает риск дублирования, но не гарантирует доставку каждого предложения.

Один экземпляр приложения использует одну папку `data`. Её нужно сохранять на постоянном диске. Утрата папки означает потерю наличия, настроек и дедупликации.

## Docker на сервере

После заполнения `.env`:

```bash
docker compose build
docker compose up -d
docker compose logs -f
```

`compose.yaml` подключает постоянную папку `./data`. После запуска открой личку с управляющим ботом и выполни /login. Для остановки: `docker compose down`. Сервер должен иметь доступ к Telegram.

## Проверки без Telegram

```bash
python -m catalog_bot demo
python -m catalog_bot check-catalog examples/catalog.txt
python -m catalog_bot check-price examples/supplier_price_excerpt.txt
python -m catalog_bot check-recognition
python -m unittest discover -s tests -v
```

Тесты проверяют подбор, импорт прайса, историю цен, нулевые остатки, неизвестный остаток, регионы, дубли, неполные ответы, 425 синтетических товарных блоков, перезапуск, ошибку отправки и команды управления. Наценка проверяется отдельно: категории, точный расчёт, бюджет по цене продажи, сохранность исходных цен и истории, отсутствие повторного начисления, отмена ответа при смене правила и атомарная запись настроек. Проверены перенос сессии для Railway и защита от записи данных за пределами Volume. Автополучение по команде и по кнопке проверяется с локальным заменителем Telegram. Подключение к реальным Telegram-аккаунтам, получение прайса от живого поставщика и живая отправка при подготовке проекта не выполнялись.
