# Запуск бота автоответов на Railway

Вход в пользовательский аккаунт выполняется прямо в управляющем боте.
Локальная установка Python и ручной перенос TELEGRAM_SESSION для этого не нужны.

## Подготовка

Создай отдельного бота через [BotFather](https://t.me/BotFather) и получи BOT_TOKEN.
API_ID и API_HASH возьми в API development tools на [my.telegram.org](https://my.telegram.org).
OWNER_ID — твой числовой Telegram ID, которому доступно управление.

## Сервис и постоянный диск

1. Создай Railway-сервис из GitHub-репозитория Danya1221/45758535, ветка main.
2. Подключи Volume к этому сервису с Mount Path `/data`.
3. В Variables добавь значения из таблицы.
4. Оставь 1 replica и выключи Serverless / App Sleeping.
5. Dockerfile уже задаёт запуск `python -m catalog_bot run`. Build Command,
   Start Command, Pre-deploy Command и Healthcheck Path можно оставить пустыми.
6. Нажми Deploy. Управляющий бот запустится даже без авторизации аккаунта.

| Переменная | Значение |
| --- | --- |
| API_ID | Число из my.telegram.org |
| API_HASH | Строка из my.telegram.org |
| BOT_TOKEN | Токен нового управляющего бота |
| OWNER_ID | Твой числовой Telegram ID |
| DATA_DIR | /data |
| PRICE_BOT_USERNAME | @tech_online_seller_bot |
| PRICE_REQUEST_TEXT | /prices |
| PRICE_REFRESH_SECONDS | 600 |
| MAX_REPLIES_PER_MINUTE | 10 |
| DEDUP_SECONDS | 120 |

PRICE_BUTTON_TEXT оставь пустым. CONTACT необязателен.
RAILWAY_VOLUME_MOUNT_PATH Railway выставляет при подключении Volume.
TELEGRAM_SESSION не добавляй: авторизация будет создана автоматически.

## Вход и включение ответов

В личке с новым ботом:

1. `/start`, затем `/login` или кнопка «Войти в аккаунт».
2. Номер аккаунта в международном формате.
3. Код входа: цифры через пробелы, например `1 2 3 4 5`.
   Не пересылай сообщение Telegram с кодом: пересылка/отправка кода может
   привести к его немедленному истечению.
4. Пароль 2FA, если бот его запросит.
5. `/status` — аккаунт подключён; дождись полного прайса, детали в `/changes`.
6. `/markup` — наценка, `/chats` — выбранные группы, `/test` — проверка запроса.
7. `/run` — включить ответы. `/pause` — остановить.

Управление и вход доступны только OWNER_ID и только в личке. Временные данные
входа очищаются при завершении/отмене и по истечении пяти минут. Бот пытается
удалить сообщения с кодом и паролем. Если код неверный, можно повторить ввод;
если истёк — начать /login заново. Ограничения Telegram соблюдаются.

Авторизация хранится в `/data/account.session`, прайс и настройки — в SQLite
на том же Volume. Сохраняй Volume при обновлениях. После обычного перезапуска
аккаунт восстановится без кода. Если Telegram отзовёт авторизацию, ответы
приостановятся; повтори /login. После нового входа ответы включаются вручную.
Автополучение прайса начинается после успешного подключения аккаунта.

Не запускай второй экземпляр с тем же BOT_TOKEN и авторизацией. Бот отвечает
в исходной группе от пользовательского аккаунта; публичный домен не нужен.

Старые установки с корректным TELEGRAM_SESSION поддерживаются: при первом
запуске ключ переносится в файл на Volume. Когда файл сохранён и аккаунт
проверен, последующие запуски используют его. Невалидную старую переменную
TELEGRAM_SESSION удали из Variables, чтобы перейти на вход через /login.

Проверки выполнены с локальным заменителем Telegram. Реальные номер, код,
пароль и отправка в живые группы не использовались.
