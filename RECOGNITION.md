# Словари и проверки распознавания

Рабочие названия и цены приходят из прайса поставщика. Словарь распознавания описывает способы написать запрос: он не добавляет товары, цены или наличие.

## Как принимается решение

1. Проверяется намерение: запрос на покупку или допустимое короткое название. Сообщения продавцов и неясные отрицания пропускаются.
2. Известные названия, сокращения и формы записи приводятся к общему виду. Например, русское название бренда, слитная версия модели, единицы памяти или `1сим`.
3. Разбираются бренд, семейство и линейка, номер и версия модели, память/RAM, цвет, SIM, NFC, связь, состояние, регион и бюджет.
4. Все явно заданные ограничения проверяются по позиции из рабочего прайса. Нераспознанное слово не считается разрешением подобрать что-нибудь похожее.
5. Ответ собирается из прошедших проверку товаров и их цен. Если подходящих позиций нет, сообщение в группу не отправляется.

Явный iPhone допускает Apple iPhone. Xiaomi с таким же номером модели и памятью не становится заменой; отсутствие или нулевой остаток iPhone не снимает это ограничение. Артикул также не отменяет бренд и остальные признаки. У аксессуара отдельно учитываются изготовитель и совместимость: «Xiaomi чехол для iPhone» не означает чехол производства Apple.

Обычная модель, Pro, Pro Max, Lite, FE и другие версии различаются. Номер модели, объём памяти и буквенные суффиксы вроде `15R` не исправляются на похожие. Короткое название без бренда допускается только при достаточной однозначности в текущем каталоге.

Xiaomi, Redmi и POCO проверяются как разные линейки даже при одном владельце бренда. Изготовитель аксессуара и устройство, с которым он совместим, также не смешиваются.

`SIM` и `1sim` означают запрос физической SIM: подходит также явно указанная комбинация `SIM+eSIM`. Явный запрос `SIM+eSIM` требует этой комбинации; `2sim` и `eSIM` проверяются отдельно. Страна не подтверждает тип SIM. Если в прайсе характеристика не указана, бот её не угадывает.

## Где находятся списки

Файл [recognition_aliases.json](catalog_bot/dictionaries/recognition_aliases.json) содержит группы:

| Группа | Назначение |
| --- | --- |
| `brands` | Канонические названия брендов и известные варианты написания |
| `brand_owners` | Связь названия бренда или семейства с изготовителем |
| `versions` | Версии и сокращения модели |
| `features` | Известные словесные характеристики |
| `series` | Названия серий и семейств |
| `conditions` | Явно указанные состояния товара |
| `colors` | Названия цветов и их варианты записи |
| `units` | Единицы памяти и размеров после числа: GB/TB/мм и известные словесные формы |
| `fuzzy_brands` | Ограниченный список брендовых слов для безопасной коррекции опечаток |
| `contextual_versions` | Сокращения, допустимые только в соответствующем контексте |

У каждого канонического названия хранится список его вариантов. Новое написание добавляется в соответствующую группу; разные модели или оттенки не нужно объединять ради получения ответа. Изменение словаря применяется после перезапуска приложения.

Коррекция опечатки ограничена брендовыми словами. Она не превращает неизвестный номер, артикул, память или версию в ближайшее имеющееся значение. Произвольная опечатка может остаться нераспознанной и привести к пропуску запроса.

## Как проверить изменение

```bash
python -m catalog_bot check-recognition
python -m unittest discover -s tests
```

Первая команда работает без Telegram, токена и авторизации. Она сравнивает результат подбора с независимыми ожидаемыми идентификаторами и возвращает ошибку, если хотя бы один сценарий не прошёл. Можно передать другой корпус:

```bash
python -m catalog_bot check-recognition examples/recognition_cases.json
```

В [recognition_cases.json](examples/recognition_cases.json) находятся учебный конкурентный каталог, ручные запросы и группы производных вариантов. Цены этого каталога вымышленные; он используется только проверочным инструментом. Ожидаемые идентификаторы заданы в данных и не вычисляются тем же подбором, который проверяется. В отчёте ручные и производные сценарии учитываются отдельно.

При добавлении формы написания добавь также проверочный запрос с ожидаемыми идентификаторами. Для нового положительного случая полезен похожий отрицательный: другая модель, бренд, память, версия или SIM. Проверочный каталог должен содержать конкурирующие позиции одновременно.

Для проверки своего рабочего прайса используй `/test текст запроса` в управляющем боте. Он показывает распознанные признаки, нормализацию и причины отсева, не отправляя сообщение в группы.
